# Vela Widgets 产品与界面设计文档

- 文档版本：v0.9
- 更新日期：2026-10-02
- 文档状态：原型实现中；日历、待办、右键菜单和偏好设置已有可运行原型，视觉方案见《[界面设计规范](界面设计规范.md)》
- 目标平台：Windows 桌面
- 技术栈：Tauri 2 + Rust + Vue 3 + TypeScript

> **设计说明：** 本文定义产品规则、范围和技术方案。视觉、尺寸档位和组件布局以《界面设计规范》为准。本文的文字线框只表达信息层级，不代表最终外观。仍标为【待确认】的事项可以继续调整。

## 1. 产品定位

Vela Widgets 是一款本地优先、安静常驻、可以自由摆放的 Windows 桌面组件软件。用户把日历、待办等独立小窗口放在桌面上，通过一个普通程序形式的中控管理窗口统一管理组件和全局设置。日常启动只恢复桌面组件，不自动打开中控，也不创建系统托盘图标。用户右键组件，在菜单中点击“Vela 偏好设置”打开中控。

核心场景是随时查看日期、记录任务、勾选完成，以及按自己的桌面布局调整组件位置和显示层级。视觉精致感来自清晰排版、克制材质和可靠交互，可参考 macOS 桌面组件和桌面增强软件的完成度，但不照搬具体界面。

第一版专注日历、待办及其管理体验。不嵌入或控制其他应用，不接入 Windows Win+W Widgets 面板，不默认连接第三方日历或云服务。

## 2. 已确认的产品约束

以下规则优先于其他默认建议。

1. **组件启用管理和全局设置都在同一个中控管理窗口内。** 不创建独立的全局设置窗口。
2. **中控是普通程序窗口，不是桌面组件。** 它使用普通应用窗口层级和标准窗口操作，不跟随组件的置顶、置底或背景透明设置。
3. **中控默认不打开。** 软件首次启动、登录自动启动以及后续正常启动，均不自动弹出中控。
4. **中控入口只放在组件右键菜单。** 菜单项名称固定为“Vela 偏好设置”，点击后打开或激活同一个中控。不设置常驻管理按钮或更多按钮。
5. **不创建系统托盘图标或托盘菜单。** 软件在桌面上呈现接近 Windows 原生组件的存在感。
6. **组件不出现在任务栏和 Alt+Tab 窗口切换列表中。** 只有中控打开时，Vela 的普通管理窗口才出现在这些位置。
7. 关闭中控只关闭管理窗口；后台程序和已启用组件继续运行。
8. **组件采用固定尺寸档位（小 / 中 / 大），不支持拖拽边缘自由缩放。** 每个档位有独立排版，材质不随尺寸变化。

其他尚未决定的事项使用【待确认】标记，文档按推荐默认值继续展开。

## 3. 产品结构

### 3.1 常驻主程序

在当前用户会话内运行，负责组件生命周期、窗口状态、配置、本地数据及退出流程。不创建托盘。无需 Windows 服务，也无需另起独立守护进程。

### 3.2 桌面组件窗口

日历和待办分别拥有独立窗口，可以各自移动、切换尺寸档位、改变层级和关闭。每类组件第一版默认只有一个实例。

### 3.3 中控管理窗口

一个按需打开的普通程序窗口，包含组件列表、单组件配置及所有全局设置。界面采用导航与内容区结构，不设计成常驻桌面卡片。

中控具备标准标题栏、最小化、最大化、关闭及边缘缩放；打开时正常出现在任务栏和 Alt+Tab 中。默认普通层级，不提供组件式置底模式。关闭后释放管理窗口及其 WebView，后台继续运行。

### 3.4 组件右键菜单

右键组件任意非输入区域打开统一菜单。菜单是独立的原生磨砂小窗口（Windows 11 亚克力质感），而不是系统纯色菜单，以便与组件材质保持一致。

“Vela 偏好设置”是唯一的中控打开入口。右键快捷设置直接修改组件自身状态，不另建设置窗口。

```text
组件右键菜单（当前实现）
┌──────────────────────────┐
│ 新建待办                  │ ← 仅待办组件
│──────────────────────────│
│ Vela 偏好设置             │ ← 打开唯一中控
│ 始终置顶 / 取消置顶        │
│──────────────────────────│
│ 尺寸          [小][中][大] │
│──────────────────────────│
│ 关闭此组件                │
└──────────────────────────┘
```

锁定位置在中控的组件页设置。退出 Vela 位于中控的“关于”页。最后组件的关闭限制按第 6.4 节处理，菜单项会显示“至少保留一个组件”。【待确认】“找回全部组件”与置底层级尚未加入菜单。键盘菜单键或 Shift+F10 触发菜单尚未实现。

### 3.5 本地数据

由 Rust 统一管理，保存全局设置、组件配置、窗口布局和待办。推荐 SQLite，不由各前端窗口分别保存正式数据。

### 4.4 组件功能取舍

【待确认】日历事件。推荐第一版只做日期展示，不引入事件编辑、重复规则和提醒。不默认接入 Outlook、Google Calendar 或 Windows 日历。

【待确认】待办复杂度。推荐任务标题、完成状态和可选截止日期。截止日期精确到日，不设置截止时刻，不发送到期通知。

未完成任务默认按逾期、今天、未来、无截止日期分组排序，同一天按创建顺序。已完成任务进入独立筛选，可取消完成。

【待确认】日历联动。推荐第一版独立运行。后续联动可以让选中日期筛选该日到期待办，但新建任务不得无提示地继承日历所选日期。

```text
后台常驻程序
├─ 日历组件窗口
│  ├─ 日期与月历
│  └─ 右键菜单

├─ 待办组件窗口
│  ├─ 待办列表与输入
│  └─ 右键菜单（含 Vela 偏好设置）
└─ 中控管理窗口（默认未打开）

   │  ├─ 我的组件：总览与启用开关

   │  └─ 待办：显示、层级、尺寸、锁定位置
```

单组件配置仍属于中控内部页面或侧面详情区。所有管理入口定位到同一个管理窗口，不重复创建中控或全局设置窗口。

## 6. 用户操作流程与状态语义

### 6.1 首次启动

不打开中控，不创建托盘。为使右键入口立即可用，默认在主显示器工作区内显示一个日历组件。组件可短暂提示“右键打开 Vela 偏好设置”，提示结束后不保留管理按钮。

用户右键日历 → 点击“Vela 偏好设置” → 中控打开到“我的组件” → 选择启用待办、调整组件配置或全局设置 → 关闭中控，继续使用桌面组件。登录自启动保持关闭，不静默开启。

【待确认】首次默认组件。推荐只开启日历，待办关闭。首次全部关闭会导致没有右键入口，因此不沿用先前的全部关闭建议。

### 6.2 后续启动

后台读取配置 → 校验显示器 → 恢复已启用组件。不创建托盘，中控不打开，不抢焦点，也不因上次退出前曾打开而自动恢复。若配置异常导致没有可用组件，尝试恢复默认日历；若全部组件创建失败，明确显示启动错误并允许重试或退出，不静默留下无法操作的后台进程。

### 6.3 从组件进入管理

右键组件 → 点击“Vela 偏好设置” → 打开或激活唯一中控 → 默认进入“我的组件”，突出来源组件。组件开关、单组件配置和全部全局设置均在中控内完成。

中控已经打开时复用现有窗口；已最小化时恢复。“Vela 偏好设置”使用固定文字名称，不在组件上增加对应按钮，也不设置额外的设置窗口入口。

### 6.4 关闭与退出

| 操作 | 即时结果 | 下次启动 |
| --- | --- | --- |
| 启用组件 | 创建组件窗口，保留或恢复已有布局 | 恢复该组件 |
| 关闭组件 | 释放窗口，保留配置及业务数据 | 不打开该组件 |
| 关闭中控 | 只关闭并释放管理窗口 | 不自动打开中控 |
| 最小化中控 | 标准最小化到任务栏 | 不决定下一次启动行为 |
| 退出软件 | 组件、管理窗口与后台全部退出 | 按保存的组件状态恢复 |

【待确认】最后一个组件的关闭策略。推荐运行时至少保留一个已启用且可交互的组件：最后一个组件的关闭操作不可执行，并显示“至少保留一个组件；如需全部移除，请退出 Vela”。要更换唯一组件，可先启用另一个，再关闭原组件。中控同时提供“退出 Vela”，避免用户为了结束程序寻找不存在的托盘。

第一版不提供“暂时隐藏全部组件”，也不提供会隐藏最后入口的单组件隐藏。退出软件即可移除全部组件，并保留启用配置。以后若加入隐藏功能，必须先确定不依赖托盘或其他偏好设置入口的恢复方式。

此项是解决唯一入口可达性的默认设计建议，并非用户已经确认的限制。

### 6.5 找回窗口

“定位”短暂突出或抬高指定组件，结束后恢复原层级，不修改其长期配置。组件因被其他窗口遮挡、显示器变化或系统显示桌面行为而不可达时，可再次启动程序请求恢复组件可见性；该操作不打开中控，偏好设置入口仍只有组件右键菜单。

“找回全部组件”恢复已启用组件的可见状态，并修正屏幕外位置。关闭的组件不被自动启用。

## 7. 视觉与交互规范

完整的视觉规范（色板、材质、字号、各尺寸布局、右键菜单、偏好设置和动画）见《[界面设计规范](界面设计规范.md)》。本节只保留总体原则。

整体以 Windows 11 Fluent 为基础，组件尺寸体系参考 macOS 桌面小组件。组件使用原生磨砂材质加半透明着色，浅色与深色各有一套中性色板，强调色只用于今天、选中、主按钮和关键数字。组件优先保证日期和任务状态的识别，中控优先清晰和操作效率。

| 项目 | 当前设计 |
| --- | --- |
| 字体 | Segoe UI Variable / Segoe UI / Microsoft YaHei UI，不依赖在线字体 |
| 背景 | 原生 HostBackdropBrush 磨砂，叠加浅色 247,248,250 或深色 34,34,36 着色 |
| 文字 | 黑白透明度分四级，不使用偏蓝灰硬编码色 |
| 强调色 | 默认 #3b67b8，提供 8 个预设色 |
| 背景透明度 | 0–100% 可调，默认 12%，只影响着色层 |
| 组件圆角 | 8–30 可调，默认 19；原生磨砂按同一圆角裁剪 |
| 动画 | 120–180 ms 轻量反馈，尊重减少动画设置 |
| 可访问性 | 清晰焦点、无障碍名称；状态不只依靠颜色 |

透明度只影响背景，不降低文字和控件的可读性。高对比度模式和实色回退【待确认】。

早期 PNG 概念稿已不再作为参考，以界面设计规范和当前原型为准。

## 8. 日历组件设计

提供三档尺寸，默认“大”。各档线框见界面设计规范第 6 节。

| 档位 | 尺寸 | 内容 |
| --- | --- | --- |
| 小 | 170 × 170 | 今天：星期、大日期、年月、周数 |
| 中 | 364 × 170 | 左侧今天信息，右侧迷你月历，可切换月份、回到今天 |
| 大 | 364 × 384 | 完整月历：切换月份、选择日期、回到今天、选中日期的相对描述 |

- 不设置管理按钮或更多按钮；右键任意非输入区域打开软件菜单。
- 小号整块可拖动，中号左侧可拖动；大号只有标题栏可拖动，日期格用于点选。
- 小号及中号左侧只表示今天，不随选择改变；中号右侧可浏览其他月份。
- 今天使用强调色实心，选中日期使用强调色浅底，二者形状和填充都不同。
- 左右按钮切换月份；“今天”回到当前月份并选中今天，只在偏离今天时出现。
- 大号月历固定 6 行，中号按月份显示 5 或 6 行；不加入事件区。
- 节假日与调休分别可控制显示，内置中国大陆 2026 年官方年度安排；未收录年份不推算。自动更新默认关闭，开启后最多每 24 小时检查项目公开文件，手动检查可随时执行。数据经过校验后保存至本地 SQLite，失败保留原有数据，更新即时同步到所有日历窗口。公开更新源已发布在 GitHub main 分支。原生更新客户端使用 Windows 系统 HTTPS 与系统代理支持；断网或超时会显示对应原因并保留原有数据。

### 8.1 节假日数据维护与发布（已确认）

采用“项目维护者人工更新 GitHub 文件，软件按版本获取”的方案，不由客户端自动抓取或解析政府网站。

1. 官方公布年度放假安排或调整通知后，维护者核对放假日期及调休上班日期，并记录官方来源。
2. 手动更新 GitHub 项目仓库中的 `data/holidays/china.json`，保存完整的年份、日期、节日名称和日期类型；普通周末不作为官方假期记录。
3. 提高数据的 `revision` 版本号，更新 `updatedAt`，并同步修改 `data/holidays/manifest.json` 中的版本号；校验通过后，将两个文件在同一提交中推送至 main 分支。
4. 软件访问这两个文件的公开原始文件地址：先读取 `manifest.json` 的版本号，只有版本比本地新时才下载 `china.json`。这属于假期数据更新，用户无需升级软件。
5. 下载后校验文件格式、版本一致性、年份、有效日期、重复日期及来源；通过后与已有年份合并并保存至本地 SQLite，立即刷新日历。失败时保留原有数据并显示检查结果。

日历日常按日期查询本地数据，不依赖联网显示。自动检查默认关闭，用户开启后最多每 24 小时检查一次；手动“立即检查”不受该间隔限制。首次发布前在线地址不可用，但内置年度数据仍可使用。未收录年份提示尚未收录，不根据农历或往年安排猜测官方放假和调休。

维护者负责数据内容的正确性，软件校验不能替代人工核对。具体文件格式及发布步骤见项目开发目录下的 `Vela/data/holidays/README.md`。
- 【待确认】键盘方向键移动所选日期，尚未实现。

【待确认】一周起始日。推荐周一，可在中控的日历配置中改为周日。

| 小 | 170 × 170 | 未完成数量和前 3 条任务，可直接勾选 |
| 中 | 364 × 170 | 左侧计数与“新建”，右侧最多 4 条任务，带截止日期，超出显示“还有 N 项” |
| 大 | 364 × 384 | 完整列表：未完成／已完成筛选、编辑、删除、截止日期 |

- 不设置管理按钮或更多按钮；右键菜单提供“新建待办”和“Vela 偏好设置”。
- 新建通过组件内居中浮层完成，入口为右键菜单、中号“新建”按钮和大号“＋”按钮。浮层随尺寸精简，小号只保留输入和“添加”。
- Enter 创建，Esc 取消；截止日期在浮层内选择，精确到日。
- 大号中点击任务标题进入行内编辑；勾选完成不打开编辑器。
- 逾期显示“已逾期”文字并使用红色，不只用颜色区分。
- 完成后移入已完成筛选，可取消完成。
- 空状态只放一个小对勾标记和提示，不使用大面积装饰图。
- 保存失败保留输入并在组件内提示，不伪装成已经保存。
- 【待确认】删除撤销、长标题两行展示、未完成任务分组排序尚未实现。

浮层限制在组件窗口内，不会被窗口边缘裁切。

## 10. 中控管理窗口设计

### 10.1 窗口性质

中控是软件的普通管理界面，窗口标题为“Vela 偏好设置”，默认 1000 × 720，最小 780 × 580。采用标准程序窗口框架，支持最小化、最大化、关闭与缩放；系统支持时使用 Mica 背景。

组件的圆角、透明度、置顶或置底配置不影响中控。中控使用普通层级，默认实色背景，正常显示在任务栏和 Alt+Tab 中。

窗口按需创建，不作为后台必须存在的隐藏窗口。关闭后释放资源；重新打开恢复上次尺寸和页面，但启动程序时不自动恢复它的可见状态。

### 10.2 主布局

中控采用 Windows 11“设置”应用的风格：原生标题栏与窗口按钮，Mica 背景，左侧搜索与分组导航，右侧为卡片式设置项（图标、标题、说明、控件）。下方线框只表示结构，具体视觉见界面设计规范第 9 节。

### 10.3 单组件配置

在同一个中控内容区展示。

已实现：在桌面显示、窗口层级（普通／始终置顶）、组件尺寸（小／中／大）、锁定位置；日历另有一周起始日。【待确认】定位、显示器选择、恢复默认布局和外观覆盖尚未实现。

组件右键菜单中的层级、尺寸与中控共享同一份状态，不维护两套配置。

### 10.4 全局设置

| 页面 | 内容 |
| --- | --- |
| 外观 | 颜色模式（浅色／深色／跟随系统，带动态预览）、强调色（8 个预设）、组件圆角（8–30）、背景透明度（0–100%） |
| 启动 | 登录 Windows 时启动（开关已预留，【待确认】功能尚未接入）；启动时只恢复组件，不打开中控 |
| 关于 | 版本、数据保存位置、退出 Vela |

外观设置即时生效并自动保存，失败时在窗口内提示，组件与中控同步更新。颜色模式预览动画：点击某个模式时播放一次切换演示；不点击时浅色和深色循环重放该演示，“跟随系统”在白天与黑夜之间交替；页面加载时不播放。详见界面设计规范第 10 节。

【待确认】自定义取色、文字大小、单组件外观覆盖、备份恢复、导出待办和重置布局以后再加。加入时，重置布局与清空待办分开；恢复备份和清空数据须说明影响范围并经用户确认。

## 11. 组件窗口行为

### 11.1 移动、尺寸与锁定

组件使用独立的无边框顶层窗口，不支持边缘缩放，也不响应双击最大化。尺寸只在小（170 × 170）、中（364 × 170）、大（364 × 384）三档间切换，入口为右键菜单和中控组件页。切换时保持左上角位置，超出屏幕时移回屏幕内，并重新应用圆角裁剪。

小、中号整块可拖动，大号只从标题栏拖动；按钮、输入框等控件不触发拖动。拖动结束约 450 ms 后保存位置，尺寸档位立即保存。锁定后禁止拖动，但仍可切换尺寸、编辑待办、选择日期和打开中控。

组件不出现在任务栏和 Alt+Tab 是已确认需求，不是可选偏好。Tauri 的跳过任务栏能力与 Alt+Tab 排除需分别验证。Windows 原生适配可评估工具窗口样式 WS_EX_TOOLWINDOW，同时避免与强制显示任务栏样式冲突；该样式在 Windows 文档中明确用于排除任务栏和 Alt+Tab。无边框外观、输入、焦点及菜单行为仍需实机验证。

不能为了隐藏窗口切换项而禁止组件激活：待办输入必须正常支持键盘与中文输入法。中控始终按普通程序窗口处理，打开或最小化时保留任务栏和 Alt+Tab 入口，关闭后移除。

### 11.2 普通、置顶与置底

| 模式 | 含义与行为 |
| --- | --- |
| 普通 | 默认模式，与普通应用参与窗口层级排序；用户点击可获焦点，启动恢复不抢焦点 |
| 置顶 | 保持在普通非置顶窗口上方；不承诺覆盖其他置顶窗口或特殊全屏界面 |
| 置底 | 兼容模式，尽量位于其他应用窗口下方；不等于嵌入桌面壁纸或图标层 |

Tauri 2 提供置顶和置底接口，可作为实现入口。Windows 的 HWND_BOTTOM 调整窗口 Z 顺序，不会自动把窗口放入桌面 Shell 层。窗口激活可能改变排序，因此置底与可交互性需要共同设计。

置底默认约定：闲置时应用置底策略；用户主动点击、编辑或定位时允许暂时抬高；失去焦点后恢复。切换层级先解除旧模式，避免置顶与置底同时生效。应用失败时显示实际状态与失败原因，允许回退普通层级。

不得承诺普通置底在 Win+D 后始终可见。真正依附 WorkerW／Progman 等 Shell 窗口的方案属于后续专项评估，需验证 Explorer 重启、焦点、图标点击和系统版本差异，不作为第一版架构前提。

【待确认】置底发布门槛。推荐提供兼容模式，验证通过后确认稳定性标识；未通过时明确标为实验功能，不能包装为稳定桌面嵌入。

### 11.3 多显示器与位置恢复

保存首选显示器标识及辅助匹配信息、逻辑尺寸、相对工作区位置、原工作区尺寸和缩放信息。显示器编号或名称不能被假设为永久唯一标识。

恢复规则：

1. 原显示器可用时恢复逻辑尺寸与相对位置，并限制在当前工作区内。
2. 分辨率或任务栏变化时按原相对位置映射，再修正越界。
3. 原显示器不可用时迁移到主显示器，多个组件错开摆放。
4. 显示器重新连接后不立即跳回，提供“恢复原位置”。
5. 临时迁移保留首选布局；用户主动拖动后才更新首选位置。
6. 工作区很小时使用紧凑布局与内部滚动，保证右键区域和主要操作可达。

显示器坐标可能为负。逻辑尺寸与物理坐标明确区分，按目标屏幕 DPI 转换，不对全局坐标统一乘一个比例。监听窗口缩放、系统显示变化、休眠恢复等事件，并重新校验布局。

中控同样具备防越界和 DPI 恢复，但不与组件共享摆放规则或显示层级。

## 12. 初步技术架构

### 12.1 模块关系

```text
用户操作
├─ 组件右键菜单（优先原生菜单）
├─ 中控管理窗口（Vue，按需打开）
├─ 日历组件窗口（Vue）
└─ 待办组件窗口（Vue）
          │
          │ 操作请求／状态通知
          ▼
Rust 常驻主程序
├─ 内置组件注册表与生命周期
├─ 窗口管理与显示器适配
├─ 待办业务规则
├─ 设置、布局与数据访问
└─ 自启动、单实例、入口保护及退出
          │
          ▼
本地 SQLite 数据库
```

Rust 是业务状态和正式数据的唯一管理者。Vue 负责呈现、输入和短暂交互状态。中控与组件可以使用同一份前端资源，按窗口身份加载对应视图，并按需加载页面。

组件生命周期不依赖中控存在，不把中控作为组件的必需父窗口或所有者；任务栏和窗口切换排除通过组件自身的窗口样式实现。关闭中控不能连带关闭、隐藏或最小化组件。

一个组件窗口不意味着一个独立 Rust 程序，但 WebView2 使用多进程模型，每增加一个 WebView 都可能增加渲染资源，不能由单个主程序推断极低内存占用。

### 12.2 前端选型

推荐继续使用 Vue 3 + TypeScript，以 Composition API 组织组件。必要时使用 Pinia 管理单窗口状态，不把 Pinia 当跨窗口共享状态。不需要 SSR 或完整网站框架。

当前没有足以改用 WPF 或 Electron 的明确技术障碍。Windows 特有行为通过小范围原生适配层补足，避免把平台逻辑散落到前端。

### 12.3 内置组件注册

采用编译期内置注册表，每个组件声明类型标识、名称、描述、前端视图、默认尺寸档位与可用档位、默认配置及版本、创建与关闭处理、允许的业务能力。

组件类型和实例标识分开，第一版仍每类一个。窗口标识与实例绑定，无需动态插件加载、远程组件包或第三方脚本协议。

### 12.4 生命周期

| 操作 | 流程 |
| --- | --- |
| 启用组件 | 检查重复实例 → 读取配置 → 创建隐藏窗口 → 加载数据与界面 → 应用布局、层级及系统窗口样式 → 保存启用状态 → 显示 |
| 关闭组件 | 校验最后入口保护 → 提交或处理未保存编辑 → 保存最终布局和关闭状态 → 销毁窗口及订阅，保留数据 |
| 恢复显示 | 重新校验显示器和数据 → 显示窗口，不默认抢焦点 |
| 打开中控 | 创建或复用唯一管理窗口 → 导航到目标页面 → 用户主动操作触发激活 |
| 关闭中控 | 处理未保存编辑 → 保存窗口布局及页面 → 销毁管理窗口，后台继续运行 |
| 启动软件 | 单实例检查 → 初始化数据 → 恢复已启用组件并校验入口可达性；不创建托盘或中控 |
| 退出软件 | 提交待保存状态 → 关闭窗口与数据库 → 退出，不清除组件启用配置 |

启用状态与实际运行状态分开，例如“已启用，本次恢复失败”。失败不能误报为运行正常，也不能阻断其他组件。Rust 主程序的崩溃仍会影响全部窗口，第一版不增加独立进程隔离体系。

中控开启状态不属于启动恢复项。上次打开过、最小化过或退出时仍打开，均不改变默认不打开的规则。

### 12.5 跨窗口状态同步

窗口打开时读取完整状态；修改由 Rust 校验并提交；提交后返回结果并通知相关窗口。恢复或重新打开时再次读取状态，不能假设事件永远不会遗漏。

Rust 校验操作来源。组件只拥有自身窗口操作及相应业务能力；自启动、备份恢复和全局重置由中控经 Rust 执行。界面使用本地资源，不加载远程网页。

### 12.6 单实例与自启动

使用 Tauri 单实例插件，防止创建两套组件。已运行时，用户再次显式启动程序仅请求恢复或找回组件，不打开中控；登录自启动产生的重复启动安静结束。重新启动程序是组件找回机制，不是额外的偏好设置入口。

登录自启动默认关闭，使用 Tauri 自启动插件管理。界面区分应用注册状态与系统是否允许启动；用户在系统中禁用后，不反复重新注册。自启动只恢复组件，不打开中控。

## 13. 本地存储与数据管理

### 13.1 方案比较

| 方案 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| JSON／Tauri Store | 配置直观，实现简单 | 待办查询、迁移和一致性需自行处理 | 适合纯配置或早期演示 |
| SQLite | 待办查询、事务、迁移、备份统一 | 需要访问层和数据版本管理 | 推荐第一版采用 |

推荐一个 SQLite 数据库统一保存全局设置、组件配置、窗口布局、待办和数据库版本。不维护 JSON 与数据库的双重正式配置源。

### 13.2 概念数据结构

| 数据域 | 内容 |
| --- | --- |
| 全局设置 | 主题、强调色、组件圆角、背景透明度、一周起始日 |
| 组件配置 | 实例与类型、启用状态、专属配置、外观覆盖、层级、锁定 |
| 窗口布局 | 组件或中控身份、首选显示器、逻辑尺寸、相对位置及恢复信息 |
| 待办 | 标识、标题、截止日期、完成状态、创建／修改／完成时间 |
| 版本管理 | 数据库版本及必要的配置版本 |

中控窗口布局可保存，但不保存为启动时自动显示。自启动开关需与操作系统状态核对，数据库偏好不是唯一事实来源。

### 13.3 写入与恢复规则

- Rust 通过专用数据库任务处理读写，避免阻塞窗口线程；可采用 rusqlite。
- 第一版单连接串行处理即可，不强制引入 WAL 或大型连接池。
- 窗口拖动结束约 450 ms 后保存位置；尺寸档位切换后立即保存。
- 待办及时事务提交，不等退出时一次性保存。
- 截止日期存日期值，不转换为 UTC 午夜；创建、修改和完成记录存时间戳。
- 数据库迁移先备份；迁移失败保留原数据并提供恢复路径。
- 备份使用 SQLite 一致性备份机制，不直接复制正在写入的数据库文件。
- 恢复前验证格式、版本和内容，保留恢复前备份；不同设备恢复布局时重新适配显示器。

【待确认】备份方式。推荐第一版支持手动完整备份／恢复和待办导出，自动定期备份以后再评估。

## 14. 低资源占用策略

不为理论性能牺牲清晰交互，也不为两个组件设计复杂渲染框架。

- 中控默认不创建，关闭后释放 WebView。
- 未启用组件不创建窗口；关闭组件清理显示监听、订阅和刷新计时器。时钟工具的到期调度由应用后台保留，关闭组件不取消闹钟或正在运行的计时器／秒表。
- 日历按跨日更新，在系统时间变化和休眠恢复时重新校准。
- 待办在数据变化时更新，不轮询数据库。
- 组件被系统隐藏或不可见时暂停无必要动画和计时器；WebView 挂起作为测量后的优化。
- 不以高频抢层级轮询维持置底。
- 默认无网络请求、在线字体、天气轮询或常驻系统监视。
- 资源测量包含 Rust 与相关 WebView2 进程，而非只看主程序。

【待确认】具体资源预算。默认目标为静止时 CPU 接近空闲、没有持续轮询、长时间运行无持续内存增长。内存上限在原型实测后确定，不提前承诺未经验证的数字。

## 15. 技术风险与验证重点

| 风险 | 可能表现 | 应对 |
| --- | --- | --- |
| 置顶与焦点 | 恢复抢焦点，菜单被遮挡 | 后台恢复不主动激活；验证层级切换、菜单及输入 |
| 置底与桌面层级 | 点击抬高、Win+D 隐藏、Shell 变化 | 明确兼容边界，保留定位入口，专项验证 |
| 混合 DPI | 跨屏尺寸或坐标错误、文字模糊 | 区分物理坐标与逻辑尺寸，按目标屏幕适配 |
| 显示器切换 | 窗口留在不可用屏幕 | 工作区校验、临时迁移和首选布局保留 |
| 无边框组件 | 圆角异常、控件误拖动、切换尺寸后磨砂错位 | 固定尺寸档位；按尺寸区分拖动区域；尺寸或缩放变化后重新裁剪原生磨砂 |
| 系统窗口呈现 | 组件出现在 Alt+Tab，或待办无法正常输入 | 分别验证任务栏与 Alt+Tab 排除、焦点、中文输入法和原生菜单 |
| 唯一入口可达性 | 所有组件被关闭或不可达，无法打开偏好设置 | 首次默认日历、最后入口保护、再次启动找回；全部创建失败时明确报错 |
| 中控生命周期 | 关闭后程序退出或保留无用 WebView | 区分管理窗口关闭与退出，无中控时仅组件和后台运行 |
| 长期常驻 | 内存增长、隐藏后持续活动 | 清理资源，测量整个进程树与长时间运行 |
| 数据保存 | 假保存、迁移失败、备份缺失数据 | 事务、错误反馈、版本迁移和一致性备份 |
| 登录自启动 | 系统禁用、路径变化、重复启动 | 插件注册、系统状态核对、单实例 |
| WebView2 安装 | 缺运行时、离线安装失败 | 安装时检测，明确在线与离线安装策略 |

## 16. 后续验收标准

以下为进入实现阶段后的验收要求，不表示当前已经完成实现或测试。

### 16.1 中控与入口

1. 首次、正常及登录自启动均不自动打开中控。
2. 不创建系统托盘图标；首次默认组件使右键入口可达。
3. 每个组件右键菜单中的“Vela 偏好设置”打开或激活同一个中控，组件上无管理按钮或更多按钮。
4. 组件配置和全部全局设置均在中控内完成，不出现第二个设置窗口。
5. 中控正常出现在任务栏和 Alt+Tab，支持标准最小化、最大化和关闭。
6. 关闭中控后组件继续运行；中控最小化后可从组件入口恢复。
7. 退出时中控打开不导致下次启动自动打开。
8. 组件不出现在任务栏和 Alt+Tab；只有打开的中控以普通程序窗口出现。
   同时验证 Windows 任务视图中的窗口呈现，确保组件不会作为普通应用切换项暴露。
9. 再次启动软件只找回组件，不打开中控。
10. 最后入口保护、退出 Vela 和全部组件创建失败的反馈均可用。

### 16.2 组件与显示器

1. 两组件分别保存启用状态、位置、尺寸和层级。
2. 关闭待办组件不删除待办数据；最后一个组件不能被普通关闭操作移除。
3. 普通、置顶和置底切换后，界面显示与实际结果一致。
4. 置底验证涵盖点击编辑、失焦、Win+D、Explorer 重启及层级切换。
5. 覆盖 100%／125%／150%／200% 混合缩放、负坐标副屏、热插拔及休眠恢复。
6. 原屏幕不可用时组件仍可找回，不自动覆盖用户的首选布局。
7. 小、中、大三档下右键菜单都可打开，日期浏览、待办勾选和新建都可用；切换尺寸后窗口不越出屏幕，圆角与磨砂对齐。

### 16.3 数据与资源

1. 保存失败保留用户输入，不呈现为已永久保存。
2. 数据备份可恢复，恢复前保留原数据。
3. 系统日期与时区变化不会导致日期型截止日期偏移一天。
4. 单组件、两组件、中控打开和中控关闭等状态均测量整个进程树；全部组件加载失败时不遗留不可操作的后台进程。
5. 反复打开关闭中控及组件后，无持续资源增长。
